## 0. 阅读指引与结论摘要

### 0.1 一句话定位

**Prism 是一个「macOS 优先」的 Emby 客户端：用 Apple TV app 式的信息层级 + Infuse 级的播放体验，做三栏原生窗口，而不是把移动端 App 放大到 Mac 上。**

### 0.2 十条结论（TL;DR）

1. **首页是胜负手，不是媒体库。** Emby 官方首页把「未看完 / 接下来 / 最新 / Live TV」放在最前，这是它最正确的决定；Prism 必须继承，并且把「继续观看」做成首屏第一屏、可键盘直接起播。
2. **详情页决定「像不像原生 App」。** Swiftfin 在 PR #492 中明确以「more like the Apple TV app」为目标重写条目页，用 backdrop + logo + 毛玻璃渐变；这是 Apple 生态用户的心理基线，Prism 应直接对齐。
3. **播放器要做「可预期的控制层」，不要做「炫技的手势层」。** Swiftfin PR #593 把手势与按钮做成「完全可自定义」✅（[PR #593](https://github.com/jellyfin/Swiftfin/pull/593)），这在触屏上是加分项；但 Mac 上用户依赖固定键位（mpv / IINA / YouTube / Netflix / Emby 五家对 `空格`、`F`、`M`、`←/→` 高度一致，见 §4.6），自定义会破坏肌肉记忆。Mac 上键盘 > 手势。
4. **Infuse 的播放引擎是标杆，交互是短板。** Mac App Store 的一条用户长评原文：「there don't seem to be a lot of keyboard commands… It's overly reliant on the mouse.」◐（[评价页](https://apps.apple.com/us/app/infuse/id1136220934?platform=mac&see-all=reviews)，用户评论非官方声明）。这就是 Prism 的差异化空位：**同样的画质，Mac 原生的操作手感。**
5. **VidHub / Fileball 的护城河是「多协议接入」，不是 Emby 体验。** 它们把 Emby/Jellyfin/Plex/SMB/WebDAV/云盘塞进一个 App。Prism 不应跟进堆协议，应把 Emby 一条链路做深（Emby 的 PlaybackInfo、章节、trickplay、多版本）。
6. **多服务器必须是「一等公民」，但要克制。** 侧边栏底部一个服务器胶囊 + 设置里的服务器管理页即可；跨服务器聚合首页/搜索放 **v1.1**，v1.0 只做「切换 + 各自独立的首页缓存」。
7. **macOS 的搜索属于工具栏，不属于侧边栏。** Apple HIG 的 Toolbars 页面把「search fields」列为工具栏的三类内容之一，macOS 一节要求「每个工具栏项都要有对应的菜单命令」✅（[HIG · Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)）；HIG 的 Keyboards 页面把 `⌘F` 定为标准「Find」、`⌥⌘F` 为「跳到搜索框」✅（[HIG · Keyboards](https://developer.apple.com/design/human-interface-guidelines/keyboards)）。因此把「搜索」做成 ⌘F 的工具栏搜索框 + 侧边栏一个可点击入口（聚焦同一搜索框），避免两个搜索实现。
8. **三栏不是「到处三栏」。** 首页/搜索用两栏（侧边栏 + 内容），媒体库浏览用三栏（侧边栏 + 网格 + 详情）。用同一个 `NavigationSplitView` 动态切换 `columnVisibility`，不要两套壳。
9. **播放内核锁定 libmpv，代价要提前认。** v1.0 用纯 libmpv（MPVKit / SPM）换取全格式直通（MKV/HEVC/DTS/TrueHD/ASS/PGS），字幕与音轨完全由客户端引擎渲染，不依赖服务端转码烧录。代价是**失去系统级能力**：libmpv 渲染层不进 `AVPlayerLayer`，因此没有 `AVPictureInPictureController`、也无法用 `AVRoutePickerView` 做 AirPlay 视频投送。v1.0 的替代是「置顶迷你播放窗（NSPanel）+ 全窗口播放页」；自研 PiP 与 AirPlay（屏幕镜像）放 v1.1。
10. **砍掉的东西要写进文档。** v1.0 明确不做：音乐、下载、Live TV/DVR、远程控制其他设备、Trakt、跨服聚合、播放列表。理由与替代方案见 §6.1 的「v1.0 明确砍掉」表。

### 1.3 分项解读（证据 → 判断 → 对 Prism 的动作）

#### 1.3.1 连接与登录

- **证据**：Emby 官方对 Emby Connect 的描述是「一个账号，你的所有 Emby 服务器」——用 PIN 流程代替输入「URL、IP、端口、用户名、密码」，且明确「媒体不经过 Connect 中转，设备直连服务器」✅（[Emby Connect](https://emby.media/connect.html)）。Swiftfin 用 Jellyfin 的 Quick Connect 做同样的事 ✅。
- **判断**：连接流程是**首次体验的全部**。用户在这一步流失，后面做得再好也没用。
- **动作**：
  - 欢迎页给三条并列路径：`输入服务器地址` / `Emby Connect 登录` / `从剪贴板识别`（粘贴 `http://192.168.1.10:8096` 自动填充）。
  - 地址校验分三层：格式 → 可达性（`/System/Info/Public`）→ 版本兼容（返回 `ServerName`/`Version`/`Id` 后显示「已找到：客厅 Emby · 4.8.0」）。
  - **不做**「扫码登录」（macOS 无摄像头场景占比低，收益小）。

#### 1.3.2 首页结构

- **证据**：Emby 官方对 macOS 版的表述是「打开就看你最可能想看的：没看完的、最新未看的电影、所有在追剧的下一集、Live TV 正在播」，并且「首页完全可自定义」✅（[Emby for macOS](https://emby.media/emby-theater-macos.html)）。Plex 新版则把 Watchlist 提到顶层导航、把「个人媒体库」集中到独立 tab ✅（[Plex Experience Preview Release Notes](https://forums.plex.tv/t/release-notes-for-plex-experience-preview-apple-tv/903004/1)）。
- **判断**：首页的价值 = **减少决策成本**，不是「展示全部内容」。Emby 的顺序（继续 → 接下来 → 最新）比 Plex 的「推荐流」更适合自建媒体库用户（他们的库是「自己选的」，不需要算法推荐）。
- **动作**：固定四段式首页（见 S04）。「推荐」只做「同库高分/同导演」，不做跨库算法流。

#### 1.3.3 详情页

- **证据**：Swiftfin PR #492 明确写「make items more like the Apple TV app」，实现为三种呈现（Compact Poster / Compact Logo / Cinematic），并用 BlurHash 取平均色做渐变「延伸」图片，模仿 Apple 的做法；剧集页有「Season 与 Episode 选择器」，且承认「季集导航问题未彻底解决」✅（[PR #492](https://github.com/jellyfin/Swiftfin/pull/492)）。
- **判断**：**backdrop + logo + 取色渐变** 是 Apple 生态的「高级感公式」，成本不高、收益极高；但「季集导航」是全行业公认的难点，Prism 必须一次做对（季选择器 + 集横向滚动 + 当前集高亮 + 自动定位到「下一集未看」）。
- **动作**：电影与剧集共用一套「Cinematic Header」组件，但剧集多一个 Season Picker 与 Episode Rail（见 S08 / S09）。

#### 1.3.4 播放器

- **证据**：Swiftfin PR #593 把播放器重写为「受 iOS 16 原生播放器影响」，提供手势全自定义、按钮可排序、滑杆颜色/类型可选、字幕字体/字号/颜色/延迟、时间戳显示方式 ✅（[PR #593](https://github.com/jellyfin/Swiftfin/pull/593)）。反观 Infuse for Mac 的一条 App Store 用户长评（原文）：「there don't seem to be a lot of keyboard commands. For example, "Command" "I" in a lot of other players like VLC will bring up codec information... **It's overly reliant on the mouse.**」◐（[Infuse · Mac App Store 评价页](https://apps.apple.com/us/app/infuse/id1136220934?platform=mac&see-all=reviews)；该页为动态渲染，引用的是页面内可见的用户评论，非官方声明）。
- **判断**：移动端「可自定义」= 自由；桌面端「可自定义」= 不确定。Mac 用户要的是**肌肉记忆**：空格、←→、F、⌘F、Esc。
- **动作**：v1.0 **不开放**控制条自定义；提供「键盘优先 + 鼠标可发现」的固定控制条；把「自定义」留给 v2.0 的「高级」开关（默认关闭）。

#### 1.3.5 字幕与音轨

- **证据**：Swiftfin 官方文档给出 VLC 与 Native(AVPlayer) 的能力矩阵：**Native 不支持字幕轨选择、不支持音轨选择**（HLS 不兼容），ASS/SSA/SRT 等格式仅 VLC 支持 ✅（[players.md](https://github.com/jellyfin/Swiftfin/blob/main/Documentation/players.md)）。Infuse 宣称支持 PGS/ASS/VobSub 等全格式 + OpenSubtitles 一键下载 ✅（[Infuse 功能页](https://firecore.com/infuse)）。
- **判断**：这份矩阵恰好是「为什么不能只做 AVPlayer」的最好证据。Apple 原生栈在**轨道选择**上受 HLS 限制，一旦走服务端烧录，字幕就从「可切换的文本」退化成「画面的一部分」——用户改不了字号、改不了延迟、也换不了语言，而且每条字幕都要服务器重新转码一次。Infuse 之所以在 Apple 生态里「字幕无对手」，靠的正是自带的解复用与渲染层。
- **动作（v1.0 前提已变更）**：
  - **v1.0 即采用纯 libmpv（MPVKit / SPM），单引擎，不做 AVPlayer 双轨**。
  - 字幕：由 libmpv 的 `sub-*` 属性族直接控制——轨道枚举走 `track-list`，延迟走 `sub-delay`，字号/描边/位置走 `sub-font-size` / `sub-border-size` / `sub-pos`；**ASS/SSA 保留原始样式与特效**（不降级为纯文本），PGS/VobSub/DVB 走位图字幕渲染。字幕菜单（S11）因此是「引擎能力的直接映射」，而不是「服务端返回了什么就只能用什么」。
  - 音轨：`aid` 属性即时切换，AC3/E-AC3/DTS/DTS-HD/TrueHD/FLAC/Opus 由 libmpv 解码或直通；音轨菜单（S12）显示真实声道数与码率，**不需要服务端把 DTS 降级成 AAC**。
  - 转码从「默认路径」降级为「兜底路径」：只在带宽不足、服务端强制、或用户手动选低画质时触发，且 UI 必须显式标注「转码播放」。
  - **代价（必须写进验收）**：libmpv 的输出不走 `AVPlayerLayer`，因此 §1.3.8 列出的系统能力缺失需要专门设计替代。

#### 1.3.6 多服务器与远程控制

- **证据**：Emby Connect 官方页的定位就是「One account. Your Emby Servers.」✅（[emby.media/connect.html](https://emby.media/connect.html)）；Plex 新版发布说明把「Centralized media libraries in a dedicated tab」「Option to favorite libraries」列为卖点 ✅（[Plex 发布说明](https://forums.plex.tv/t/release-notes-for-plex-experience-preview-apple-tv/903004/1)）。
- **判断**：多服务器是**重度用户**（家里 NAS + 朋友共享服）的刚需，但对新用户是噪音。用「渐进披露」：只有一个服务器时，侧边栏底部不显示切换器。
- **动作**：服务器胶囊 + `⌘⇧S` 切换面板；**v1.0 只做「切换」，不做「聚合」**（各服务器首页/搜索独立）；跨服务器聚合搜索与统一首页放 v1.1；远程控制（Cast 到另一台 Emby 会话）v2.0。

#### 1.3.7 音乐与 Live TV

- **证据**：Emby for macOS 官方页把「The Best Way to Watch Live TV」「Never Miss a Show with Emby DVR」「A Beautiful Way to Play Your Music」+「Easy Now Playing Queue」并列为核心卖点 ✅（[emby.media/emby-theater-macos.html](https://emby.media/emby-theater-macos.html)）；Plex 的音乐由独立 App Plexamp 承担 ✅（[plex.tv/plexamp](https://www.plex.tv/plexamp/)）。
- **判断**：音乐与 Live TV 都是「有则加分、无则不痛」的长尾；且在 macOS 上，音乐与 Apple Music 竞争、Live TV 与 Plex/Emby 官方竞争，Prism 早期没有胜算。libmpv 本身能放音频，但「音乐库」需要专辑/艺术家/队列一整套 IA，与影视的网格模型不同，硬塞进 v1.0 会拖垮首页。
- **动作**：音乐放 v1.1（侧边栏一级入口 + 底部 Now Playing 条，不做独立 App）；Live TV 放 v2.0，且仅在服务端检测到 tuner 时出现。

#### 1.3.8 libmpv 的「系统能力缺口」与替代设计（v1.0 必须提前认账）

选 libmpv 是「用系统集成度换格式覆盖率」。缺口是确定的，必须逐条给出替代方案，否则会在开发后期变成体验塌方。

| 失去的系统能力 | 原因 | v1.0 替代方案 | 后续版本 |
|---|---|---|---|
| **画中画（PiP）** | `AVPictureInPictureController` 只接受 `AVPlayerLayer`；libmpv 走 `CAMetalLayer` 自绘 | **置顶迷你播放窗（NSPanel，`.floating` 层级，无边框、可拖拽、可缩放、锁定 16:9、悬停显示迷你控制条）** + 全窗口播放页。迷你窗与主窗口共享同一个 mpv 实例，切换不重载、不丢进度 | 自研 PiP 窗口（v1.1） |
| **AirPlay 视频投送** | `AVRoutePickerView` 的 AirPlay 视频通道需要 `AVPlayer` 资产 | **不支持**。UI 上**不放置** AirPlay 按钮（避免「按钮在但点了没用」）；设置 › 播放 给一行说明：「如需投送到 Apple TV，请使用系统屏幕镜像（控制中心 › 屏幕镜像）；镜像会带上窗口边框且无法后台播放。」 | v2.0 再评估 |
| **Now Playing / 媒体键** | 与渲染层无关，可独立使用 | **可保留**：手动写入 `MPNowPlayingInfoCenter`（标题/剧集信息/时长/进度/封面）+ 注册 `MPRemoteCommandCenter`（play/pause/toggle/seek/next/previous），媒体键与「正在播放」小组件因此可用 ✅ | v1.0 |
| **音频 AirPlay** | 音频输出走 mpv `ao=coreaudio`，跟随系统输出设备 | 系统输出切到 AirPlay 音箱时音频可出，但**视频仍在本地**（音画分离），设置里给警示文案；不做专门入口 | v1.0 |
| **HDR / Dolby Vision** | mpv 在 macOS 上走 `gpu-next` + `target-colorspace-hint`，DV 支持有限 | HDR10/HLG 支持直通与色调映射；DV Profile 5/8 以 HDR10 回退呈现，设置项标注「Dolby Vision 将以 HDR10 呈现」 | v1.1 跟进 |
| **系统字幕样式（`AVTextStyleRule`）** | 不适用（非 AVPlayer 渲染） | 用 mpv 自有字幕渲染 + 设置页样式项（字体/字号/颜色/描边/位置），语义与系统字幕设置对齐但独立存储 | v1.0 |
| **起播速度 / 低功耗** | AVPlayer 有系统级预加载与硬解 | `hwdec=videotoolbox` 硬解；首帧目标 ≤ 800ms（1080p 局域网）；起播前预读 2 秒；暂停 30s 后自动释放解码器 | v1.0 |

> **结论**：PiP 与 AirPlay 视频投送是 v1.0 的**公开缺口**，必须写进发布说明、App 内「关于 › 已知限制」、以及官网下载页的「功能对比」。让用户在下载前就知道，比让他在使用中发现要好。

## 2. 信息架构（IA）

### 2.1 五条 IA 原则

1. **一级导航只放「去处」，不放「功能」。** 首页/电影/剧集/合集/播放列表/搜索/下载 是去处；「刷新」「设置」是功能 → 设置放侧边栏底部（同时是 ⌘, 菜单命令），刷新放工具栏与 ⌘R。
2. **层级不超过三层。** 侧边栏（L1）→ 网格/列表（L2）→ 详情（L3）。详情内的「季 → 集」是**同一层的切换**，不是第四层。
3. **导航与内容分离。** 侧边栏选中项决定中间栏内容；右侧详情栏只在「有选中条目」时展开（Mail 式）。返回键（⌘[）只在详情栏内生效。
4. **状态是全局的，不是页面的。** 当前服务器、当前用户、播放队列、正在播放的条目，都是 App 级状态；切换侧边栏不打断播放。
5. **渐进披露。** 单服务器用户看不到「切换服务器」；无 tuner 看不到 Live TV；无下载任务时侧边栏不出现「下载」；无音乐库不出现「音乐」。

**列可见性规则**

| 场景 | `columnVisibility` | 说明 |
|---|---|---|
| 首页 / 搜索 / 设置 / 关于 | `.doubleColumn` | 详情栏隐藏，内容栏占满 |

**关键决策**

- **「搜索」是侧边栏项目，但实现是工具栏搜索框。** 点侧边栏「搜索」→ 中间栏变成搜索落地页（最近搜索 + 热门），同时工具栏搜索框获得焦点。避免「两个搜索页」。
- **「设置」在侧边栏底部而不是中间栏。** 设置以**独立 Settings 窗口**（`Settings` scene）打开，不占三栏，符合 macOS 习惯（⌘, 打开独立窗口）。
- **不使用 `Section` 折叠**（v1.0 项目少，折叠反而增加点击）。
- **不在侧边栏放「最近播放」**（首页已覆盖，重复会稀释层级）。

### 2.4 多服务器切换：三个入口 + 一个状态模型

| 入口 | 位置 | 交互 | 版本 |
|---|---|---|---|
| ① 服务器胶囊 | 侧边栏底部、设置上方 | 点击 → 弹出菜单（服务器列表 + 状态点 + 「管理服务器…」+「添加服务器…」）；`⌘⇧S` 全局唤起 | v1.0 |
| ② 设置 › 服务器 | 设置窗口第 5 个面板 | 列表：名称/地址/用户/状态；可重命名、排序、设为默认、删除、重新登录 | v1.0 |
| ③ 欢迎页 / 添加流程 | 首次启动、或菜单「文件 › 添加服务器…」 | 同 S02 | v1.0 |

**服务器状态模型（胶囊上的点）**

| 状态 | 颜色 | 文案 |
|---|---|---|
| 已连接 | 绿 | 已连接 · Connected |
| 连接中 | 黄（脉冲） | 正在连接… · Connecting… |
| 令牌失效 | 橙 | 需要重新登录 · Sign in again |
| 离线 | 灰 | 离线 · Offline |
| 版本不兼容 | 红 | 服务器版本不受支持 · Unsupported server |

**切换语义（必须写进实现契约）**

- 切换服务器 **不销毁窗口**，只替换数据源；侧边栏选中项回落到「首页」。
- 每个服务器独立保存：用户令牌、首页布局缓存、上次浏览位置、排序/筛选偏好、播放器偏好（可选全局）。
- 正在播放时切换服务器 → 弹确认「当前正在播放，切换将停止播放」，或（推荐）允许切换并**继续播放**（播放会话绑定旧服务器，仅浏览切到新服务器）。v1.0 采用后者，播放器标题旁显示服务器名。
- 服务器同名/同库名时，用「服务器色点」区分（每台服务器分配一个稳定色相，取 `hash(serverId)`）。

### S01 · 欢迎与引导（Welcome）

**目的**：在 10 秒内让用户完成「这台 Mac 上有一个能连 Emby 的 App」的认知，并进入连接流程。

**关键元素**
- 全窗口品牌区：Prism 光谱棱镜标识（静态或极轻的渐变流动，尊重「减弱动态效果」）。
- 主标题：「欢迎使用 Prism」/「Welcome to Prism」。
- 副标题：「连接你的 Emby 服务器，开始观看。」/「Connect your Emby server to start watching.」
- 三个并列操作（大按钮 + 说明文字）：
  1. **连接服务器**（主按钮）→ S02
  2. **使用 Emby Connect** → S02（Connect 模式）
  3. **从剪贴板粘贴地址**（仅当剪贴板含 http(s) 链接时出现）
- 底部：版本号 + 「Prism 不是 Emby 官方产品」的轻量声明（合规必需）。

**交互**
- ↵ 默认触发「连接服务器」。
- 拖拽 URL 到窗口任意位置 = 粘贴地址。
- 首次启动无网络 → 「连接服务器」仍可点，进入 S02 后由 S02 报错（不在欢迎页拦截）。

**状态**

| 状态 | 表现 |
|---|---|
| 空态 | 不适用（本页即空态） |
| 加载态 | 不适用 |
| 错误态 | 不适用 |

### S02 · 添加服务器（Add Server）

**目的**：把「一串地址」变成「一个已验证、可登录的服务器对象」。

**关键元素**
- 分段控件：`服务器地址` / `Emby Connect`。
- 地址模式：
  - 输入框（自动聚焦），占位符 `http://192.168.1.10:8096`。
  - 「自动补全」：只输入 `192.168.1.10` 时自动补 `http://` 与 `:8096`。
  - 「发现」区域（v1.1）：局域网扫描到的服务器列表（名称 + 地址 + 图标）。
  - 高级选项（折叠）：「使用 HTTPS」「跳过证书校验（不推荐）」。
- Connect 模式：邮箱 + 密码 → 服务器列表（该账号关联的服务器，含在线状态）。
- 主按钮：「连接」；次按钮：「返回」。
- 右侧（窗口足够宽时）：一张示意图/说明卡「在哪里找到服务器地址？」→ 展开三步图文。

**交互**
- 输入 500ms 防抖后自动探测 `/System/Info/Public`，成功则输入框下方出现绿色行「已找到：客厅 Emby · 4.8.0」，主按钮变为「继续」。
- 探测失败不立刻报错，等用户点「连接」再报（避免打字过程中红屏）。
- `⌘V` 粘贴整条 URL（含路径）→ 自动剥离路径，仅保留 scheme/host/port。
- 回车 = 连接；`Esc` = 返回欢迎页。

**状态**

| 状态 | 表现 | 文案 |
|---|---|---|
| 空态 | 输入框为空 + 灰字提示 | 「输入服务器地址，例如 192.168.1.10:8096」 |
| 加载态 | 输入框右侧 spinner + 按钮禁用 | 「正在连接…」/「Connecting…」 |
| 错误：格式错误 | 输入框红边 + 行内错误 | 「地址格式不正确，请包含 http:// 或 https://」 |
| 错误：不可达 | 错误卡片 + 重试 | 「无法访问该地址。请确认服务器已启动，且与本机在同一网络。」+「重试」+「检查防火墙」 |
| 错误：非 Emby | 错误卡片 | 「该地址不是 Emby 服务器（返回内容无法识别）」 |
| 错误：版本过旧 | 警告卡（可继续） | 「服务器版本 4.6.0 低于建议的 4.7.0，部分功能可能不可用。」+「仍然继续」 |
| 错误：证书 | 警告卡 | 「服务器证书无效。」+「查看证书」+「仍然继续（不安全）」 |

### S03 · 登录（Sign In）

**目的**：用最少的输入换取一个长期有效的 AccessToken，并让用户知道「登录的是谁、哪台服务器」。

**关键元素**
- 顶部：服务器身份条（服务器图标 + 名称 + 地址 + 状态点）——让用户随时确认「我在登录哪台」。
- 用户头像网格（若服务器开启了「公开用户列表」）：点击头像直接进入密码输入，减少打字。
- 用户名 / 密码输入框（密码带「显示」眼睛）。
- 「记住我」开关（默认开）。
- 主按钮「登录」。
- 分隔线 + 「使用快速连接（PIN）」：显示 6 位 PIN + 「在 Emby 网页端输入此代码」+ 二维码（v1.1）。
- 底部：「切换服务器」文字按钮。

**交互**
- 自动聚焦用户名（或密码，若已记住用户名）。
- ↵ 提交；提交中按钮显示 spinner 且禁用。
- 失败 3 次后出现「忘记密码？」提示（指向服务器管理员，Prism 不提供找回）。
- 登录成功 → 淡出到首页，同时后台预取首页第一屏数据（避免首页再转圈）。

**状态**

| 状态 | 表现 | 文案 |
|---|---|---|
| 空态 | 用户名/密码为空 | 占位符「用户名」「密码」 |
| 加载态 | 按钮 spinner + 表单禁用 | 「正在登录…」 |
| 错误：凭据错误 | 密码框红边 + 抖动（一次） | 「用户名或密码不正确」 |
| 错误：账号禁用 | 错误卡片 | 「该账号已被服务器管理员禁用」 |
| 错误：服务器离线 | 错误卡片 + 重试 | 「服务器无响应，请稍后再试」 |
| 错误：令牌过期（二次进入） | 顶部黄条 | 「登录已过期，请重新登录」 |
| PIN 过期 | PIN 区域倒计时归零 | 「代码已过期」+「刷新代码」 |

### S04 · 首页（Home）

**目的**：让用户「打开就能点播放」，不需要先做选择。

**关键元素（自上而下，固定顺序）**
1. **Hero（可选，v1.1）**：继续观看中最近的一项，用 backdrop 铺满内容栏顶部，叠加标题 + 「继续播放 · 还剩 32 分钟」+ 进度条。v1.0 不做 Hero（降低首屏复杂度），直接从横滑开始。
2. **继续观看 Continue Watching**：横向海报卡（2:3），卡片底部叠加进度条与「剩余 32 分钟」；悬停显示 ▶ 与「从 12:34 继续」。
3. **接下来 Next Up**：按剧集聚合，卡片显示「S2E5 · 剧集名」，右上角小角标「下一集」。
4. **最近添加 Recently Added**：按库分组的小标题（「电影 · 最近添加」「剧集 · 最近添加」），每组一行横滑。
5. **因为你看了《X》**（v1.1）：同导演/同类型，最多 20 项。
6. 每段右侧「查看全部 ›」→ 中间栏 push 到对应的「更多」列表。

**交互**
- 横滑：触控板两指横扫；`⇧` + 滚轮横向滚动；悬停到行边缘出现 ‹ › 按钮。
- 卡片点击 → 右侧详情栏加载（不跳页）；双击卡片 / 卡片上的 ▶ → 直接播放。
- 右键卡片：播放 / 从上次位置继续 / 标记已看 / 收藏 / 在 Finder 中显示（v1.1，需服务端支持）/ 前往剧集。
- 刷新：`⌘R`；下拉刷新不适用（macOS 无下拉手势）。
- 键盘：Tab 进入卡片区，←→ 在行内移动，↑↓ 换行，↵ 打开详情，空格播放。

**状态**

| 状态 | 表现 | 文案 |
|---|---|---|
| 空态（新用户，无观看记录） | 保留「最近添加」，隐藏「继续观看 / 接下来」 | 「开始观看后，这里会显示你的进度」 |

| 加载态 | 骨架屏：2 行海报占位 + 标题条 | — |
| 错误：拉取失败 | 顶部内联错误条（不遮挡已有内容） | 「部分内容加载失败」+「重试」 |
| 错误：服务器离线 | 整页错误 + 服务器胶囊变灰 | 「无法连接到 客厅 Emby」+「重试」+「切换服务器」 |

### S05 · 媒体库网格（Library Grid）

**目的**：在大量条目中快速定位；提供「扫视」而非「阅读」的浏览体验。

**关键元素**
- 顶部工具栏（中间栏内）：库名称 + 条目数（「共 1,284 部」）+ 视图切换（网格/列表）+ 筛选按钮 + 排序菜单。

- 底部：无限滚动加载 + 「已全部加载」提示。
- A-Z 跳转条（v1.1，右侧竖排字母，仅列表/名称排序时显示）。

**交互**

### S10 · 播放器（Player）

**目的**：不打断观看的前提下，让用户随时能「暂停、跳转、换字幕、换音轨、全屏、退出」。

**结构（三层）**

```
┌──────────────────────────────────────────────────────────────┐
│ ① 顶部条（悬停/移动鼠标出现）                                  │
│   ‹ 返回   《片名》 S2E5 · 标题            [服务器名]   ⤢ 全屏 │
│                                                              │
│                                                              │
│                     ② 画面（libmpv 渲染层）                    │
│                        CAMetalLayer / vo=libmpv               │
│                                                              │
│                                                              │
│ ③ 控制条（自动隐藏）                                           │
│   ▶/⏸   ⏪10  ⏩10        12:34 ──────●────── 1:42:10        │
│   [章节刻度]  [缓冲进度]  [悬停缩略图预览]                     │
│   字幕  音轨  速度  迷你窗  画质  下一集                       │
└──────────────────────────────────────────────────────────────┘
```

**关键元素**
- 顶部条：返回（Esc 退出全屏 → 再 Esc 关闭播放器）、标题（剧集显示 S/E）、服务器标识（多服务器时）、全屏切换。
- 中央：单击画面 = 播放/暂停（可配置为「单击暂停」默认开）；双击 = 全屏。
- 控制条：
  - 播放/暂停（44×44 点击区）。
  - ±5 秒（默认；可在设置改 5/10/15/30）。`J`/`L` 为 ∓10 秒。
  - 进度条：已播（强调色）+ 缓冲（半透明白）+ 章节刻度（小竖线）+ 悬停预览（缩略图 + 时间）。
  - 时间：当前 / 总时长（可切换「剩余时间」）。
  - 字幕按钮（弹出 S11）、音轨按钮（S12）、速度（0.5×–2×）、**迷你窗（弹出置顶 NSPanel）**、画质（转码/直通切换）、下一集（剧集）。
  - **不提供「画中画」按钮与「AirPlay」按钮**（libmpv 无系统 PiP、无 AirPlay 视频通道；见 §1.3.8）。设置 › 播放 中给「迷你窗」与「屏幕镜像」的文字说明。
- 自动隐藏：播放中 3 秒无操作隐藏；暂停时保持显示；鼠标移动/任意键显示。

**交互（键盘优先，完整表见 §4.6）**
- `空格`/`K` 播放暂停；`←/→` ±5s；`⇧←/⇧→` ±30s；`J/L` ∓10s；`⌥←/⌥→` 上/下一章；`⌘←/⌘→` 上一集/下一集；`↑/↓` 音量 ±5%；`M` 静音；`F` 或 `⌃⌘F` 全屏；`⌃⌘P` 迷你窗；`S` 字幕菜单；`A` 音轨菜单；`Z/X` 字幕延迟 ∓0.1s；`V` 字幕显隐；`1–9`/`0` 跳百分比。**完整表与依据见 §4.6。**
- 触控板：双指左右滑 = seek（带惯性）；双指上滑 = 显示控制条；捏合 = 全屏/退出。
- 鼠标滚轮：音量（默认）或 seek（设置可选）。
- 退出时保存进度（本地立即 + 上报服务器，失败静默重试）。

**状态**

| 状态 | 表现 | 文案 |
|---|---|---|
| 加载（起播） | 中央 spinner + 「正在准备播放…」+ 取消按钮 | 「正在准备播放…」 |
| 缓冲 | 进度条上缓冲段 + 中央小 spinner（>1s 才出现） | — |
| 转码中 | 顶部小标签「转码播放 · 1080p 8Mbps」 | 「转码播放」 |
| 错误：源不可用 | 覆盖层 + 重试/换版本 | 「无法播放该文件」+「重试」+「选择其他版本」 |
| 错误：转码失败 | 覆盖层 | 「服务器转码失败，请检查服务器性能或选择更低画质」 |
| 错误：网络中断 | 覆盖层（可恢复） | 「连接已中断，正在重连…」+ 倒计时 |
| 播放结束 | 剧集：10 秒倒计时自动下一集 + 「取消」 | 「10 秒后播放 S2E6」 |
| 无权限 | 覆盖层 | 「服务器拒绝播放（可能需要 Emby Premiere）」 |

## 4. macOS 平台适配要点

> 设计原则一句话：**「像 macOS 应用，而不是像 iOS 应用跑在 Mac 上」。** 所有决策优先服从 HIG 与系统习惯，其次才是品牌表达。

### 4.0 平台基线

| 项 | 值 | 依据 |
|---|---|---|
| 最低系统 | **macOS 15 Sequoia**（`MACOSX_DEPLOYMENT_TARGET = 15.0`） | `project.yml` 与 `docs/ROADMAP.md`（项目已确认决策） |
| 语言/框架 | Swift 6（严格并发）+ SwiftUI，AppKit 仅用于播放器视图嵌入与窗口细节 | 同上 |
| 设计系统落点 | `Sources/PrismUI`（`PrismUI` target） | `Package.swift` 分层约定 |
| 架构依赖方向 | PrismUI → PrismData → EmbyAPI → PrismCore；PrismUI → PrismPlayback | `Package.swift` 注释 |

> 含义：所有设计可以用 macOS 15 的 API（如 `NavigationSplitView` 的 `columnVisibility`、`.searchable` 的 toolbar 行为、`@Observable`），**不需要**为 macOS 13/14 做降级分支；反之，**不要**使用 macOS 26 才有的 Liquid Glass 专属 API（HIG 已按新系统描述，但我们的基线是 15）。

### 4.1 NavigationSplitView 三栏

**结构**

```swift
NavigationSplitView(columnVisibility: $visibility) {
    SidebarView(selection: $route)          // 220–260pt
} content: {
    ContentColumn(route: route)             // min 480pt
} detail: {
    DetailColumn(selectedItem: $selectedItem) // min 420pt, ideal 640pt
}
.navigationSplitViewStyle(.balanced)
```

| 要点 | 规定 |
|---|---|
| 列宽 | 侧边栏 220pt（可拖到 180–300）；内容栏最小 480pt；详情栏最小 420pt、默认 640pt |
| 折叠 | 用户拖拽折叠；`⌃⌘S` 或「显示 › 隐藏边栏」切换；窗口 < 1040pt 自动折叠详情栏 |
| 列切换 | 用 `columnVisibility` 状态机，不用两套视图树；首页/搜索/设置 → `.doubleColumn` |
| 选中态 | 侧边栏用 `.listStyle(.sidebar)`，系统选中色；**不要**自定义选中背景（深色模式下会违和） |
| 恢复 | 记住每列的宽度与折叠状态（`@SceneStorage`） |
| 状态恢复 | `NSWindowRestoration`：重启后恢复窗口位置、选中项、滚动位置 |

**三栏的反模式（禁止）**

- ❌ 把播放器塞进详情栏（播放器必须是全窗口/独立窗口）。
- ❌ 在内容栏里再嵌一层 `NavigationSplitView`。
- ❌ 侧边栏出现三级展开（超过两级就改用内容栏列表）。

### 4.2 工具栏与搜索框

- 工具栏分区（遵循 HIG「leading / center / trailing」）：
  - **leading**：侧边栏切换按钮 + 标题（当前库名，≤15 字符）。
  - **center**：视图切换（网格/列表）、筛选、排序。
  - **trailing**：搜索框（`.searchable`，始终可见，宽度 180–260pt）+ 用户头像菜单。
- **搜索框常驻**，不做「点放大镜才展开」——Mac 用户期望随时能 `⌘F` 打字。
- 窗口变窄时，center 项自动进系统 overflow 菜单（不要自己做「更多」）。
- 播放页使用独立窗口/全屏时，工具栏隐藏（`.toolbar(.hidden)`），用自绘顶部条替代。
- 标题不使用 App 名（HIG 明令），用「电影」「剧集」「搜索」。

> 1. **HIG 标准快捷键不得抢占**（`⌘F`、`⌘,`、`⌘I`、`⌘?`、`⌘W`、`⌘M` 等）；
> 2. **跨产品一致的键位优先保留**（`空格`、`F`、`M`、`←/→`、`j/l`、数字键）；
> 3. **mpv/IINA 默认键位仅在与其他强约定冲突时才覆盖**，且覆盖必须写进本文档；
> 4. 覆盖后**原功能必须有新位置**，不能丢。

#### 4.6.1 播放与时间

| # | 按键 | 业界通行（依据） | Prism 采用 | 可自定义 | 冲突/覆盖说明 |
|---|---|---|---|---|---|
| 1 | `空格` | 全部五家一致（mpv / IINA / YouTube / Netflix / Emby） | 播放 / 暂停 | 是 | 无冲突 |
| 2 | `K` | YouTube、Netflix | 播放 / 暂停（同 `空格`） | 是 | mpv 未占用 `k` |
| 3 | `←` / `→` | mpv ±5s、YouTube 5s、Netflix 10s、Emby 快退/快进 | **±5 秒**（设置可改 5/10/15/30） | 是 | 取 mpv/YouTube 的 5s，而非 Netflix 的 10s（与 `j/l` 分工） |
| 4 | `J` / `L` | YouTube ∓10s、Netflix 无 | **∓10 秒** | 是 | **覆盖 mpv 的 `j` = 循环字幕**；字幕循环改到 `⇧[`/`⇧]` |
| 5 | `⇧←` / `⇧→` | mpv = 1 秒精确 seek；IINA = 上/下一句字幕；Emby = 快退/快进 | **±30 秒** | 是 | **覆盖 mpv 精确 seek**；理由：与 `←/→` 构成 5s/30s 两级，且 Emby 用户已有「⇧+方向键=粗调」预期 |
| 6 | `⌥←` / `⌥→` | YouTube（Mac）上/下一章；mpv 的 `⌥←/→` 是平移画面 | **上一章 / 下一章** | 是 | **覆盖 mpv 的画面平移**；平移改到 `⌃⌥←/→`（v1.1 提供） |

#### 4.6.5 实现必须遵守的优先级规则

1. **文本输入优先**：搜索框/备注框聚焦时，除 `Esc` 与 `⌘` 组合外全部交给文本系统（HIG 的 Full Keyboard Access 要求不得吞键）。
2. **`Esc` 三级回退**：全屏 → 迷你窗 → 关闭播放器，每次只退一级；`Esc` 不得直接杀进程式关窗。
3. **HIG 保护区**：`⌘F`、`⌘,`、`⌘I`、`⌘?`、`⌘W`、`⌘M`、`⌘Q`、`⌘Z/X/C/V/A` 在播放器内**不重定义**。
4. **覆盖必须留后路**：本表中每一个「覆盖」项，原功能都必须在新键位或 UI 中存在（已在「冲突/覆盖说明」列注明去向）。
5. **`responder chain` 分层注册**：不要用全局 `NSEvent` 单例硬拦；播放器视图实现 `keyDown`，未处理则 `super` 上抛给菜单系统。
6. **可自定义项**：标「是」的 **31** 项进 `设置 › 播放 › 快捷键`；重绑冲突时高亮冲突项且禁止保存。标「否」的 **6** 项（`1–9/0`、`⌃⌘F`、`Esc`、`⌘F`、`⌘I`、`?`）固定，避免用户把自己锁死或违反 HIG。
7. **发现性**：所有可自定义键位必须在「`?` 帮助浮层」与对应菜单项（如 `播放 › 字幕菜单  S`）中同时可见——HIG 要求「工具栏/快捷键能做的事，菜单里也要有」。

### 4.9 深色模式、Dock 与 Now Playing

- **深色模式**：跟随系统（默认）；设置可强制深/浅。所有自定义颜色必须走 Asset Catalog 的 Any/Dark 双值，禁止硬编码 `Color.black`（播放器控制层除外，它永远是暗色）。
- **播放器永远是暗色**：即使系统是浅色，播放器背景为纯黑（`#000`），控制层用白色 80% 透明；这是视频类应用的行业共识（避免浅色边框干扰）。
- **Dock**：显示「正在播放」进度条（`NSApp.dockTile` 可选，v1.1）；不显示徽标数字（无未读概念）。
- **Now Playing（控制中心/媒体键）**：`MPNowPlayingInfoCenter` 写入标题、剧集（S/E）、时长、已播位置、封面（`MPMediaItemPropertyArtwork`）、`MPNowPlayingInfoPropertyMediaType = .video`；注册 `MPRemoteCommandCenter` 的 play/pause/toggle/seek/next/previous；**停止播放后 5 秒清空**（避免残留）。○ 待验证：libmpv 场景下 `MPNowPlayingInfoCenter` 的进度插值是否平滑（需真机测），以及是否需要在暂停时冻结 `elapsedPlaybackTime`。
- **画中画**：v1.0 无（libmpv），用迷你窗替代；v1.1 自研。
- **窗口标题**：显示「片名 — S2E5」，不使用 App 名。

### 4.10 可访问性（与平台适配同级）

- 全键盘可达：所有交互元素可 Tab 聚焦，焦点环用系统 `focusEffect`。
- VoiceOver：海报卡 label = 「片名，2023 年，8.1 分，已观看 40%」；播放器控制条每个按钮有明确 label。
- 尊重「减弱动态效果」：关闭视差/缩放/渐变流动；骨架屏改为静态。
- 尊重「降低透明度」：毛玻璃层退化为不透明纯色。
- 对比度：正文 ≥ 4.5:1；播放器控制层加底部渐变保证可读。

## 5. 视觉方向建议

### 5.0 两个必须守住的视觉底线

1. **海报是主角，UI 是背景。** 任何装饰都不能比海报更抢眼；内容区背景要「退后」。
2. **2:3 是唯一的海报比例。** Emby/TMDB 的海报都是 2:3；混用 16:9 会让网格出现「参差的洞」。横版图（backdrop）只用于详情页头部与集缩略图。

### 5.1 方案 A：「影院暗色 + 毛玻璃」（推荐用于 v1.0 默认）

**一句话**：像影院放映厅——黑底、暖白字、海报发光，UI 只在需要时浮现。

| 项 | 规定 |
|---|---|
| 基调 | 全局深色（不跟随系统浅色时也保持深色，或仅在浅色系统下用「深灰」变体） |
| 背景层级 | L0 `#0B0B0D`（窗口底）→ L1 `#141417`（内容区）→ L2 `#1C1C21`（卡片/浮层） |
| 毛玻璃 | 侧边栏、工具栏、播放器控制条使用 `.ultraThinMaterial`（深色下叠加 `#000` 30%）；**仅这三处**使用，避免性能与「雾蒙蒙」 |
| 强调色 | Prism 光谱：主色 `#7B5CFF`（紫），渐变到 `#3EC6FF`（青）；仅用于：选中态、进度条已播段、主按钮、焦点环 |
| 文字 | 主 `#F5F5F7` / 次 `#A1A1A6` / 三级 `#6E6E73` |
| 海报处理 | 圆角 8pt；悬停时 `scale 1.03` + 阴影 `black 40% radius 16 y 8`；加载前用主色占位 |
| 氛围光 | 详情页 header 用海报主色做 120pt 高的底部渐变（模仿 Swiftfin/Apple TV 的 BlurHash 取色），透明度 ≤ 35% |
| 适用 | 夜间观影、HTPC、大屏；**v1.0 默认** |

### 5.2 方案 B：「系统原生浅色」（跟随系统，偏「资料库工具」）

**一句话**：像 Finder/Photos——白底、细分割线、系统蓝，信息密度更高，适合「管理型」用户。

| 项 | 规定 |
|---|---|
| 基调 | 完全跟随系统外观（浅/深自动） |
| 背景层级 | L0 `systemBackground` → L1 `secondarySystemBackground` → L2 `tertiarySystemBackground` |
| 毛玻璃 | 仅在侧边栏与工具栏使用系统 `.sidebar` 材质；播放器仍为纯黑 |
| 强调色 | 系统强调色（默认蓝 `#007AFF`），尊重用户在「系统设置 › 外观」中的选择 |
| 文字 | `label` / `secondaryLabel` / `tertiaryLabel`（语义色，自动适配深色） |
| 海报处理 | 圆角 6pt；悬停 `scale 1.02` + 1pt 描边 `separatorColor`；无发光 |
| 氛围光 | 无（详情页用纯色背景 + 大标题） |
| 适用 | 白天、办公场景、长时间浏览；v1.1 作为可选主题 |

### 5.4 SwiftUI 主题 Token 清单（可直接落地）

```swift

enum PrismTheme {

    // MARK: - 颜色（语义化，双主题）

        // 背景层级
        static let bgWindow      = SwiftUI.Color("bg.window")       // A: #0B0B0D / B: systemBackground
        static let bgContent     = SwiftUI.Color("bg.content")      // A: #141417 / B: secondarySystemBackground

        static let bgElevated    = SwiftUI.Color("bg.elevated")     // 浮层/弹出
```

## 6. 版本范围切分

### 6.0 范围总原则

- **v1.0 只做「影视优先」六件事**：连接、库浏览、搜索、详情、播放、续播。任何不属于这六件事的功能，一律推后。
- **每个版本都要能独立发布、独立可用**，不做「半成品开关」。
- **能力缺口显式声明**：v1.0 的 PiP/AirPlay/音乐/Live TV/下载缺失，必须在「关于 › 已知限制」与下载页列出。

### 6.1 v1.0（MVP）— 影视优先六件事

**目标**：一个 Emby 用户下载后，能在 2 分钟内连上服务器、找到片、以原画质看完，并下次接着看。

| # | 能力 | 包含界面 | 说明 |
|---|---|---|---|
| 1 | **连接** | S01 欢迎、S02 添加服务器、S03 登录 | 地址 + 账号；Emby Connect 作为可选路径；多服务器「切换」可用 |
| 2 | **库浏览** | S04 首页、S05 网格、S06 筛选排序 | 首页四段式；网格 + 筛选 + 排序；不支持合集/播放列表入口 |
| 3 | **搜索** | S14 搜索 | 单服务器内搜索；结果分组；最近搜索 |
| 4 | **详情** | S07 电影详情、S08 剧集详情、S09 季集列表 | Cinematic header；季集导航；多版本切换；相似推荐 |
| 5 | **播放** | S10 播放器、S11 字幕、S12 音轨、S13 进度预览 | **libmpv 单引擎全格式直通**；ASS/PGS 原生；键盘映射全套（§4.6） |
| 6 | **续播** | 首页「继续观看」+ 播放器进度上报 | 服务器为准；续播提示；跨设备一致 |

**v1.0 还包含的平台能力**

- 三栏 `NavigationSplitView`、工具栏搜索、右键菜单、全套快捷键（§4.4/§4.6）、触控板手势、全屏、**置顶迷你窗**、菜单栏命令、深色模式、Now Playing/媒体键、窗口状态恢复、可访问性。
- 设置 5 面板（播放/字幕/网络/外观/服务器）+ 关于（含已知限制）。
- 分发：直接下载 DMG + 公证 + Sparkle 自动更新（见 §6.6）。

**v1.0 明确砍掉（并给出理由）**

| 砍掉 | 理由 | 用户替代 |
|---|---|---|
| 音乐库 | 需要专辑/艺术家/队列一整套 IA，与影视网格模型冲突，会拖垮首页 | 用 Emby 官方客户端或网页版听音乐 |
| 下载/离线 | 与「播放内核稳定性」抢同一批工程资源；macOS 用户多为常在线 | 本地播放缓存（自动，不可管理） |
| Live TV / DVR | 需要 EPG 时间轴这一整套新布局；用户覆盖率低 | Emby 官方客户端 |
| 远程控制其他设备 | 依赖 Sessions API 与冲突处理，价值集中在多设备重度用户 | Emby 网页版 |
| 播放列表 | 入口价值低于详情页质量；v2.0 补 | — |
| 合集 | 依赖 BoxSet 数据结构与去重规则；v1.1 补 | — |
| PiP | libmpv 无系统 PiP | **置顶迷你窗**（v1.0 已提供） |
| AirPlay 视频投送 | libmpv 无 AirPlay 视频通道 | 系统「屏幕镜像」（有损） |
| Trakt / 外部同步 | 需要 OAuth 与映射，非核心 | — |
| 多服务器聚合（跨服搜索/统一首页） | 数据合并与去重规则复杂 | 手动切换服务器 |
| App Store 分发 | 沙盒限制与 libmpv 的动态库/公证链路更适合站外分发 | 官网 DMG |

### 9.3 被删除或改写的错误陈述（原文 → 更正）

| # | 原文（错误） | 更正 | 原因 |
|---|---|---|---|
| 1 | 「播放器内 `⌘F` = 切换全屏」 | `⌘F` 在播放器内**保持 Find 语义**；全屏用 `F` 或 `⌃⌘F` | HIG 标准快捷键表：`⌘F` = Find，`⌃⌘F` = Enter full screen |
| 2 | 「`[` / `]` = 字幕延迟 ∓0.1s」 | `[` / `]` 在 mpv 是**播放速度 ±10%**；字幕延迟改用 `Z` / `X`（mpv 与 IINA 一致） | [mpv manual](https://mpv.io/manual/master/) 与 [IINA input.conf](https://github.com/iina/iina/blob/develop/iina/config/iina-default-input.conf) |
| 3 | 「`A` = 音轨菜单；`⇧A` = 画面比例」 | `A` 在 mpv 是**画面比例循环**；Prism 将 `A` 定为音轨菜单，画面比例移到 `⇧A`，**并在表中标注为「覆盖」** | 同上；覆盖必须显式声明 |
| 4 | 「`↑`/`↓` 音量」未标注冲突 | 保留音量（YouTube/Netflix/IINA 三家一致），但**显式标注覆盖了 mpv 的 `↑/↓` = ±1 分钟**，1 分钟 seek 移到 `⇧PageUp/PageDown` | 同上 |
| 5 | 「Swiftfin 无 Mac 原生版（跑 iPad 版）」 | 改为「官方定位 iOS/tvOS；Mac 上可跑 iPad 版 ◐（未找到官方说明）」 | 无官方来源 |
| 6 | 「Emby macOS 版支持 Cast」 | 降为 ○ 待验证 | 无来源 |
| 7 | 「v1.0 用 AVPlayer 原生 PiP」 | 已按新决策删除，改为 NSPanel 迷你窗 | 决策变更（libmpv） |
